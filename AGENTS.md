# VibeLetter

Read `docs/IMPLEMENTATION-CONTRACT.md` for architecture and operator API conventions. Source derives from Mailcheap under MIT; retain its copyright.

- `apps/web` is the Next.js UI and backend. `apps/cli` is the context-aware operator CLI.
- SQLite uses Drizzle and better-sqlite3, with a persistent local volume. R2 stores uploads. SES sends mail. No MongoDB, Redis, paid queue service or serverless hosting.
- Schema changes use `npm run db:generate`, reviewed generated migrations, then `npm run db:migrate`. Never `drizzle-kit push` or a custom migration ledger.
- `npm run dev:web` binds localhost:3035. `npm run worker` is the separate sender process. Confirm the target DB and sending flags before starting either.
- Dev login requires development mode, explicit enablement and a loopback request origin. It must never work in production.
- Mail defaults off. Never send probes to imported or real audiences; use SES simulator or an explicitly approved recipient.
- New backend and CLI code use strict TypeScript. Retained UI and pure upstream helpers may remain JavaScript.
- Parent owns root configs, package files, lockfile, installs and publication. Parallel lanes edit only their assigned files.
- Keep credentials, local databases, `.vibeletter/`, `.hermes/` and `.agents/` untracked.
- Gates: `npm run typecheck`, `npm run lint`, `npm run build`, retained upstream tests and runtime/browser scenarios. Do not add tracked tests without explicit request.
