# VibeLetter implementation contract

## Target
Independent MIT public repo `vibelabsdotto/vibeletter`, derived from Mailcheap commit `67d13b028a6ecae9ec56d49c4b2db58019217eba`. Preserve upstream copyright. UI/editor/archive broadly preserved. npm workspaces `apps/web` and `apps/cli`. Next.js App Router holds backend; no Nest, MongoDB, Upstash, Redis, QStash or Vercel Blob. New backend/CLI in strict TypeScript. Existing JS UI/pure helpers may remain during port. No new tracked tests; use existing tests and scratch runtime/browser probes.

## Shared database
`apps/web/src/db/schema.ts` exports Drizzle SQLite tables `newsletters`, `campaigns`, `contacts`, `messages`, `events`, `suppressions`, `apiKeys`, `alerts`. Preserve original record shape: `_id` string, original property names, Date timestamps via timestamp_ms. Generate 24-char hex IDs locally. Nested settings/counters may use typed JSON columns; counters must update atomically in SQL. Indexed real columns for IDs/status/email/slug/send times, FK and unique constraints. `src/db/index.ts` exports `db` Drizzle, `sqlite` better-sqlite3, `connectDb()` readiness facade. DATABASE_PATH defaults repo `data/vibeletter.db`. WAL, FKs, busy timeout. Official Drizzle generation/migrate() and ledger. No generic Mongoose emulation/query interpreter. Port consumers to direct Drizzle or small domain repositories. Preserve pure functions and upstream security behavior.

Auth owns separate `src/db/auth-schema.ts` with Better Auth `user`, `session`, `account`, `verification`. Include in migration schema; auth lane coordinates exports with DB lane. Keep getSession()/requireSession() helper return including email for old UI actions.

## Authentication
Better Auth + Drizzle SQLite adapter. Single operator ADMIN_EMAIL, no public production signup. Explicit operator provisioning. authenticateRequest(request) supports bearer or Better Auth session. Tokens `vl_`, hashed storage, expiry/scopes, plaintext only on creation. Development login ONLY NODE_ENV=development AND DEV_LOGIN_ENABLED=true AND canonical APP_URL plus actual request host are loopback. Production always denies bypass. Don't trust forwarded host/IP. SESSION_SECRET remains recipient-link signing only. BETTER_AUTH_SECRET/BETTER_AUTH_URL/APP_URL/ADMIN_EMAIL configure auth.

API keys persist developmentOnly provenance. Nonproduction issuance and delegation from dev/unknown authority remain quarantined; new normal production issuance explicitly writes false. Unknown legacy keys default to quarantine and require production reissuance, never guessed backfill. Raw Better Auth endpoints enforce the dev-session boundary before mutation too.

## Operator API and CLI
`/api/v1/` resources: newsletters, contacts, campaigns, domains, api-keys, suppressions, overview, queue, health, uploads. Existing API contact/campaign payload remains supported. Lists `{items,total,limit,offset}`. Writes validate/authenticate, invoke shared domain services and read back actual saved record. CLI `vibeletter` under apps/cli. Contexts `~/.config/vibeletter/config.json`, optional `.vibeletter/config.json`; precedence flags > VIBELETTER_INSTANCE/VIBELETTER_TOKEN > selected context > local defaults. --context/--instance/--json, structured errors, nonzero exit. Tokens via env/file/stdin, never argv/help/logs. context set/use/list/show/remove/verify. CLI covers all exposed operations. DB migrate and operator provision are separate local operator commands.

Use original newsletter fields `name`, `slug`, `fromName`, `fromEmail`, `replyTo`, `postalAddress` and nested original settings. Contacts `newsletter` slug plus email. Campaigns `newsletter`, subject, previewText, html/markdown. `/campaigns/[id]/actions` POST action: send/test/schedule/unschedule/pause/resume/send-more/duplicate/archive-slug/pin/discard/cleanup-preview. Body `{action,...options}`. CRUD `/resource/[id]`, POST collection; domains verify/create returns DNS. Shared queue service, no second sender.

## Providers and queue
Persistent SQLite npm queue after research, standalone worker, no public callbacks. Native package owns persistence/retry/scheduling. Global rate includes welcome/confirmation/test. Live SES only SENDING_ENABLED=true, default off. No silent mock success. SES default AWS credential chain plus SES_* credentials, us-east-1. Configuration set/SNS feedback for deliveries/bounces/complaints. Live probes may use SES simulator, never real imported audiences. Uncertain transport outcomes must not auto-resend. R2 S3 env R2_ACCOUNT_ID/R2_BUCKET/R2_ACCESS_KEY_ID/R2_SECRET_ACCESS_KEY/R2_PUBLIC_URL. Local file transport only explicit dev mode, no production fallback. Upload type/size validation.

Live sending requires valid SES_CONFIGURATION_SET and SES_SNS_TOPIC_ARN matching the effective region/partition, checked at startup and provider I/O. Confirmation messages persist confirmationNonce and select history by that generation, not timestamps; sender eligibility, rendered link and final claim all use the saved nonce. Legacy missing nonce cannot acquire current consent authority, and unknown legacy transport blocks duplication pending reconciliation. SNS event receipt first-claim and all side effects share one immediate transaction, preserving existing receipt keys. Optional administrative alerts claim their cooldown in `alerts` and enqueue a `send-alert` job; producers never wait for SES. The worker re-checks ALERT_FROM/ADMIN_EMAIL/SENDING_ENABLED, takes the global pacing slot and marks the claim sending before SES I/O. Definite pre-acceptance rejections use the bounded queue retries; unknown outcomes are recorded and never resent.

## Lanes

No installs, commits, pushes, branches, worktrees, backups or deployments. Preserve others' edits. OpenFibu is read-only reference. Agent findings .hermes/reports. No new tracked tests/fixture outputs.
